1. Resumen Ejecutivo del Stack

Ganttagram es una solución de alto rendimiento para el sector construcción. Combina la agilidad de las tecnologías web modernas con la capacidad de ejecución nativa en escritorio mediante Tauri. El sistema está diseñado bajo el principio de Optimistic UI y sincronización en tiempo real.

2. Arquitectura del Frontend (Client-Side)

La aplicación utiliza una estructura Feature-Based para maximizar la escalabilidad y mantenibilidad.

2.1. Estructura de Directorios

Ruta Responsabilidad Técnica
/src/features/ Contiene módulos de negocio encapsulados (Gantt, Auth, Resources). Cada módulo tiene sus propios componentes, hooks y estilos.
/src/services/ Abstracciones de APIs externas. Principalmente firebase/config.js que inicializa la conexión con el Backend.
/src/shared/ Librería de componentes UI atómicos (Atomic Design) usados en toda la app para mantener consistencia visual.
/src/assets/ Recursos estáticos, imágenes de sistema y fuentes locales.
/src-tauri/ Capa de Rust que permite el acceso a APIs del sistema operativo (Archivos, Notificaciones, Ventanas).

2.2. Lógica de Negocio Avanzada

Uno de los componentes críticos es el motor de Dependencias entre Tareas (useDependencies):

  • Detección de Ciclos: Implementa un algoritmo de búsqueda (BFS) para evitar dependencias circulares antes de persistir en la base de datos.
  • Cálculo de Holguras (Lag): Permite definir tiempos de espera entre tareas vinculadas directamente en el modelo de datos.
  • Estado Optimista: El hook utiliza onSnapshot de Firebase para reaccionar inmediatamente a cambios remotos, actualizando el gráfico de Gantt sin recargas.

3. Arquitectura del Backend (Serverless & Cloud)

Ganttagram prescinde de un servidor tradicional en favor de una arquitectura Serverless robusta basada en Google Firebase.

3.1. Modelo de Datos (NoSQL Firestore)

Se utiliza una estructura jerárquica refinada:

/projects {document}
   ├── name, description, budget, startDate
   ├── /tasks {subcollection}
   │      ├── title, progress, startDate, endDate, resourceId, category
   ├── /dependencies {subcollection}
   │      ├── fromTaskId, toTaskId, type (FS, SS, etc), lag
   ├── /resources {subcollection}
   │      ├── name, type (Personal, Maquinaria, Materiales), cost
   └── /milestones {subcollection}
          ├── title, date, importance

3.2. Seguridad y Reglas de Negocio

La integridad de los datos de construcción se protege mediante Firestore Security Rules. Cada acceso es validado a nivel de servidor:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /projects/{projectId} {
      allow read, write: if request.auth != null;
      
      match /{allSubcollections=**} {
        allow read, write: if request.auth != null;
      }
    }
  }
}

3.3. Autenticación

Se implementa Firebase Auth con persistencia local. El flujo asegura que ningún dato sea solicitado o mostrado hasta que el token JWT del usuario sea validado por el proveedor.

4. Sistema de Diseño (Industrial-Tech Premium)

El diseño no es solo estético, es funcional (Ingeniería de Interfaz).

4.1. Variables CSS Dinámicas

En index.css, se definen tokens que cambian según el tema:

  • Modo Blueprint (Claro): Fondo `#f8fafc`, acento azul `#2563eb`. Optimizado para alta visibilidad en obra.
  • Modo Deep Slate (Oscuro): Fondo `#0f172a`, superficies `#1e293b`. Diseñado para reducir fatiga visual en oficina.

4.2. Renderizado de Gantt

El gráfico de Gantt utiliza una combinación de CSS Grid y posicionamiento absoluto calculado dinámicamente mediante hooks de React, permitiendo el escalado fluido en resoluciones 4K.

5. Despliegue y CI/CD

5.1. Producción Web (Netlify)

El despliegue se realiza mediante Netlify CLI o integración con GitHub. El archivo netlify.toml asegura el manejo de SPA Routing:

[[redirects]]
  from = "/*"
  to = "/index.html"
  status = 200

5.2. Empaquetado Desktop

Para generar los instaladores de escritorio:

# Generar instalador para Windows (.msi, .exe)
npm run tauri build
